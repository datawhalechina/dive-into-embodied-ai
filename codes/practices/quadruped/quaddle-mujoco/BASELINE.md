# Quaddle 仿真基础版 v0.1（2026-11-10）

这是固定模型、分场景配置的教学演示版本。硬件尚未到货，动力学未标定；没有声称同一个策略能覆盖所有环境，也没有把周期控制器写成 PPO 训练成果。

## 这一版可以展示什么

| 项目 | 当前范围 | 控制方式 |
| --- | --- | --- |
| 停走、转向 | 平地，目标航向 ±20° 内的行走转弯；停下再继续走 | 支撑姿态停止、有界 PI 航向反馈、目标航向渐变 |
| 平地、上坡、下坡 | 平地、3°/5° 上坡、3° 下坡；各场景独立配置 | 周期步态 |
| 下台阶 | 4 mm × 3 级，每级深 12 cm | 增加推进余量的周期步态 |
| 平缓坑洼 | 内部相邻格及进出口高差 ≤2 mm，固定种子 7 | 已有残差 PPO，未新增训练 |

`baseline.py --case all` 只运行这七项。原始独立随机 ±3 mm 坑洼、跑步、浅水和视觉自主避障不在本版通过范围内。平缓坑洼改变了地形分布，不能用来宣称原始坑洼任务已解决。

**2 mm × 3 级上台阶保留为实验展示。** 原配置在标称条件前进 0.910 m、峰值关节速度 8.919 rad/s、最大偏航 24.32°，通过原检查。但是本轮 118 次配置/起始方向评测没有找到同时通过标称与 +3° 起步的新配置；保留的原配置在六个预先指定的新条件下也全部失败。因此没有用一个退步的候选覆盖原配置，更没有将其列为稳定基础能力。

## 如何运行

在本目录中使用已经安装 `requirements-rl.lock` 的 Python 环境，并在仓库根目录先执行 `git lfs pull`。模型网格和本版附带的旧 PPO 权重均需要下载为真实文件。

```bash
# 先核对代码、模型、配置、权重与归一化统计量的 SHA-256
.venv/bin/python baseline.py --verify-only

# 重跑七项标称检查；失败会返回非零退出码
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 .venv/bin/python baseline.py

# Linux 无显示器录制完整交互过程
MUJOCO_GL=egl .venv/bin/python baseline.py --case interaction --video

# 有桌面显示的环境中实际键盘控制；macOS 使用环境内的 mjpython
.venv/bin/python command_interaction.py --interactive

# 显式运行上台阶实验，不计入上面的七项
MUJOCO_GL=egl .venv/bin/python baseline.py --case stairs_up_demo --video
```

键盘：`W` 行走，`S` 停在支撑姿态，`A/D` 增减目标航向（限制在 ±20°），`Q` 退出。转向是行走中的弧线，不是原地旋转。键盘入口与回放使用同一个控制器；本轮在无显示器环境验证了控制逻辑与回放，未做原生窗口的人工点击验收。原网页交互保持原实现，尚未移植这套 PI 控制。

实时命令退出时保存在 `outputs/interaction_live_commands.json`。离线指标回放要求指令从 0 秒开始、每段至少持续 2 秒；任意频繁按键并不包含在本次通过结论里。可用 `command_interaction.py --commands <JSON> --seconds <时长>` 回放符合该格式的指令。

## 停走和转向具体改了什么

原停止动作会把关节归零，再起步快速回到支撑姿态，首次试验在 12.261 s 出现过度倾斜，随后机身触地。现在停止时保持起步所用的支撑姿态，以 2 rad/s 限制停止目标的变化。

航向反馈加入有上限的积分补偿，消除持续方向误差；步行关节目标变化率限制为 4 rad/s。直接把目标从 −20° 切到 +20° 曾导致转向失败，因此再增加 10°/s 的航向目标过渡。所有修改都只写关节目标，不移动基座、不注入外力。仿真使用 1 ms 物理步长和固定的每 5 ms `mj_forward` 调用。

最终固定参数的十组复测全部通过：包括起始朝向、横向位置、摩擦、先等待再起步、改变指令时刻、两种转向顺序和 ±15° 小转弯。八组是前一轮条件的确认，两组是本轮未用于选参的新条件；这是有限的确定性条件测试，不是随机鲁棒性保证。

- 物理检查沿用关节速度 ≤10 rad/s、机身不触地、姿态、闭环误差和力矩等限制。
- 每个行走段沿指令方向前进 >10 cm，最后 1 秒最大航向误差 <10°。
- 停止指令后等待 1 秒，随后漂移 ≤2 cm。
- 意图转弯不使用直行任务的“世界航向偏离 <25°”判据，原始直行指标仍保存在同目录 `metrics.json`，交互验收以 `interaction_metrics.json` 为准。

## 复现与继续迭代

- `reference/baseline-v0.1.json`：场景清单、版本与文件哈希。
- `reports/baseline_2026-11-10.json`：搜索、确认、失败与已知限制。
- `reference/graded-rough-policy/`：同一旧 PPO 的权重、归一化统计量及原始训练元数据；本轮新增 PPO 步数为 0。
- `check_command_interaction.py`：控制器不改状态/外力、停止目标限速及旧台阶配置结果不变。
- `validate_interaction_release.py`：复跑十个固定交互条件。
- `optimize_baseline_heading.py`：台阶参数研究；失败结果照常落盘，不自动升级基础版。

下一轮若继续做 2 mm 台阶，应分析左右脚接触与航向响应，而不是继续只凭标称距离选参数；本轮新条件失败也说明仅围绕一个起点调参很容易过拟合。4 mm 上台阶仍按用户决定暂停。
