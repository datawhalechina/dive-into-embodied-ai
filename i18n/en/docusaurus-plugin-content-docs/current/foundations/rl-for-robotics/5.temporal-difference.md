# 5. Temporal-Difference Methods

[Temporal-difference (TD) methods](/docs/foundations/rl-for-robotics/quick-reference#td) combine ideas from Monte Carlo methods and dynamic programming. They update estimates at each step without waiting for an episode to finish.

For unfamiliar symbols, consult the [terms and formulas quick reference](/docs/foundations/rl-for-robotics/quick-reference#notation). Expand the plain-language explanations beside this chapter's formulas without leaving the page.

> **Embodied AI perspective**: TD learning is the core update mechanism behind many modern deep RL algorithms, including DQN's Q updates and DDPG/SAC's Critic updates. It lets a robot learn incrementally while interacting with its environment.

This chapter follows the [MDP reward-index convention](./2.mdp.md#21-智能体与环境交互): executing $A_t$ produces $R_{t+1}$ and leads to $S_{t+1}$; an observed transition is $s_t,a_t,r_{t+1},s_{t+1}$. In numerical updates, $R_{t+1}$ takes its observed value $r_{t+1}$. The code variables `r` and `reward` also denote the reward from this transition.

## 5.1 Temporal-difference estimation \{#51-时序差分估计}

Recall the Monte Carlo update in $\eqref{eq:constant_step_mc}$:

$$
\begin{equation}\label{eq:constant_step_mc}
V(s) \leftarrow V(s) + \alpha [G - V(s)]
\end{equation}
$$

The complete return $G$ starts at state $s$ and ends at the terminal state:

$$
\begin{equation}\label{eq:return}
G = R_{t+1} + \gamma R_{t+2} + \gamma^2 R_{t+3} + \cdots + \gamma^{T-t-1} R_T
\end{equation}
$$

Monte Carlo estimation can update values incrementally across episodes, but it must first wait for an episode to finish to obtain its complete return. This can make learning slow for long episodes and unsuitable for tasks without a clear endpoint.

**Temporal-difference (TD) estimation** instead combines the immediate reward with the estimated value of the next state:

$$
\begin{equation}\label{eq:td_update}
V(s_t) \leftarrow V(s_t) + \alpha [R_{t+1} + \gamma V(s_{t+1}) - V(s_t)]
\end{equation}
$$

<details>
<summary>In plain language: what does one TD update calculate?</summary>

Suppose the old estimate is $V(s_t)=4$, the observed reward is $1$, the next-state estimate is $6$, the discount factor is $\gamma=0.9$, and the learning rate is $\alpha=0.1$:

1. Calculate the target: $1+0.9\times6=6.4$, the immediate reward plus an estimate of the future.
2. Calculate the error: $6.4-4=2.4$. This target is above the old estimate.
3. Move partway toward it: $4+0.1\times2.4=4.24$.

$\leftarrow$ means to store the updated value, not that the old and new values are equal. If the next state is truly terminal, set its continuation value to $0$; the same other numbers give $4+0.1(1-4)=3.7$.

Quick reference: [bootstrapping, TD error, and learning rate](/docs/foundations/rl-for-robotics/quick-reference#td).

</details>

The quantity $R_{t+1} + \gamma V(s_{t+1})$ is the **TD target**, an estimate of the current return $G$. Its difference from the current value estimate is the **TD error**:

$$
\begin{equation}\label{eq:td_error}
\delta_t = R_{t+1} + \gamma V(s_{t+1}) - V(s_t)
\end{equation}
$$

Updating an estimate using another current estimate is called [**bootstrapping**](/docs/foundations/rl-for-robotics/quick-reference#td). TD combines Monte Carlo's ability to learn without transition probabilities with dynamic programming's use of existing value estimates. It can therefore update before a complete return is available.

If executing $a_t$ leads to a terminal $s_{t+1}$, there is no continuation return, so set $V(s_{t+1})=0$. The reward $R_{t+1}$ still updates the state $s_t$ from which the action was taken:

$$
\begin{equation}\label{eq:td_update_terminal}
\begin{split}
    \begin{cases} V(s_t) \leftarrow V(s_t) + \alpha[R_{t+1}- V(s_{t})]
 & s_{t+1}\text{ is terminal} \\ V(s_t) \leftarrow V(s_t) + \alpha[R_{t+1}+\gamma V(s_{t+1})- V(s_{t})] & s_{t+1}\text{ is nonterminal}\end{cases}
\end{split}
\end{equation}
$$

## 5.2 A numerical example \{#52-时序差分估计计算示例}

Consider the $3\times3$ grid world from the Monte Carlo chapter. The agent follows a random policy, starting at the upper-left corner and finishing at the lower-right corner. Actions $a_1$ and $a_2$ move right or down. The positions are states $s_1,s_2,\ldots,s_9$, with $S_0=s_1$ and terminal state $s_9$.

<Figure caption="A 3×3 grid world" width={500}>

![The 3×3 grid used to compare Monte Carlo and TD estimation](@site/docs/foundations/rl-for-robotics/figs/maze_33.webp)

</Figure>

Each step incurs reward $-1$. Entering the pit at $s_4$ adds $-3$; entering the puddle at $s_5$ adds $-0.5$. With $\gamma=0.9$, estimate the state values $V(s)$.

The following Python example compares TD and Monte Carlo estimation:

```python title="Example 1: Comparing TD and Monte Carlo estimation"
import random
from collections import defaultdict
import numpy as np
import pandas as pd
import matplotlib.pyplot as plt
import time

# ---------- Parameters ----------
gamma = 0.9
alpha = 0.1            # Learning rate (try 0.05–0.2)
episodes = 100000
states = [f"s{i}" for i in range(1, 10)]
terminal = "s9"
start = "s1"

coords = {
    "s1": (0,0), "s2": (0,1), "s3": (0,2),
    "s4": (1,0), "s5": (1,1), "s6": (1,2),
    "s7": (2,0), "s8": (2,1), "s9": (2,2)
}

# ---------- Environment ----------
def legal_actions(s):
    r, c = coords[s]
    acts = []
    if c < 2: acts.append("right")
    if r < 2: acts.append("down")
    return acts

def step(s, a):
    r, c = coords[s]
    if a == "right": r2, c2 = r, c + 1
    elif a == "down": r2, c2 = r + 1, c
    s2 = [k for k, v in coords.items() if v == (r2, c2)][0]
    reward = -1.0
    if s2 == "s4": reward -= 3.0     # Pit
    if s2 == "s5": reward -= 0.5     # Puddle
    if s2 == "s9": reward += 1.0     # Goal +1 gives net reward 0
    done = (s2 == terminal)
    return s2, reward, done

def policy(s):
    acts = legal_actions(s)
    return random.choice(acts)

def generate_episode():
    episode = []
    s = start
    while True:
        if s == terminal:
            episode.append((s, None, 0))
            break
        a = policy(s)
        s2, r, done = step(s, a)
        episode.append((s, a, r))
        s = s2
    return episode

# ---------- First-Visit Monte Carlo ----------
def first_visit_mc(num_episodes=episodes, gamma=0.9):
    V = defaultdict(float)
    N = defaultdict(int)
    for _ in range(num_episodes):
        episode = generate_episode()
        G = 0
        visited = set()
        for s, a, r in reversed(episode):
            G = gamma * G + r
            if s not in visited:
                visited.add(s)
                N[s] += 1
                V[s] += (G - V[s]) / N[s]
    return V

# ---------- TD(0) prediction ----------
def td0_value_prediction(episodes=episodes, alpha=alpha, gamma=gamma, start="s1"):
    V = defaultdict(float)  # Initialize all values to 0
    for _ in range(episodes):
        s = start
        while s != terminal:
            a = policy(s)
            s2, r, done = step(s, a)
            # TD(0) update
            V[s] += alpha * (r + gamma * V[s2] - V[s])
            s = s2
    return V

s_t = time.time()
V_mc = first_visit_mc()
t_cost_mc = time.time() - s_t
print(f"First-Visit MC time: {t_cost_mc:.2f} seconds")

# ---------- Print results ----------
grid_mc = np.array([[V_mc[f"s{r*3+c+1}"] for c in range(3)] for r in range(3)])
df_mc = pd.DataFrame(grid_mc.round(3),
                     columns=["col1","col2","col3"],
                     index=["row1","row2","row3"])
print(df_mc)

s_t = time.time()
V_td0 = td0_value_prediction()
t_cost_td0 = time.time() - s_t

print(f"TD(0) time: {t_cost_td0:.2f} seconds")

grid_td0 = np.array([[V_td0[f"s{r*3+c+1}"] for c in range(3)] for r in range(3)])
df_td0 = pd.DataFrame(grid_td0.round(3),
                      columns=["col1","col2","col3"],
                      index=["row1","row2","row3"])
print(df_td0)
```

An example output is:

```
First-Visit MC time: 0.57 seconds
      col1   col2  col3
row1 -4.43 -2.149  -1.0
row2 -2.15 -1.000   0.0
row3 -1.00  0.000   0.0
TD(0) time: 0.47 seconds
       col1   col2  col3
row1 -4.110 -2.216  -1.0

```

Both methods produce similar values in this example, with TD taking slightly less time. TD updates during an episode, which can improve learning efficiency when complete episodes are expensive to collect. Values and runtimes vary between runs.

## 5.3 Deriving the TD target \{#53-时序差分目标的推导}

Where does $R_{t+1} + \gamma V(s_{t+1})$ come from? Recall the Bellman equation:

$$
\begin{equation}\label{eq:3}
\begin{aligned}
V_{\pi}(s) & =\mathbb{E}_{\pi}\left[G_t \mid S_t=s\right] \\
& =\mathbb{E}_{\pi}\left[R_{t+1}+\gamma V_{\pi}\left(S_{t+1}\right) \mid S_t=s\right]
\end{aligned}
\end{equation}
$$

Under the expectation for a given policy, the complete return can be replaced by an immediate reward plus the discounted next-state value. This motivates the sampled approximation:

$$
\begin{equation}\label{eq:4}
G_t \approx R_{t+1} + \gamma V(s_{t+1})
\end{equation}
$$

<details>
<summary>Step by step: why is this an approximation, not an equality?</summary>

The recursion $G_t=R_{t+1}+\gamma G_{t+1}$ holds along a single trajectory. Instead of waiting for that trajectory to finish, TD replaces its unavailable $G_{t+1}$ with the current estimate $V(s_{t+1})$. That enables earlier updates but introduces estimation error.

Even the true value is an average return. Suppose the next state's subsequent return is either $2$ or $8$ with equal probability: its true value is $5$, but a particular trajectory still returns $2$ or $8$. The Bellman equation relates the corresponding conditional expectations; it does not make every trajectory's numbers identical.

Quick reference: [Bellman equation](/docs/foundations/rl-for-robotics/quick-reference#bellman) and [expectation](/docs/foundations/rl-for-robotics/quick-reference#value).

</details>

Substituting this target into the Monte Carlo update gives the TD update. The relation is about **expectations**, not equality between an individual sampled target and a complete return. A stable policy, sufficient exploration, and repeated updates are important for value estimation. As $V$ approaches $V_\pi$, the target's conditional expectation approaches $\mathbb{E}_\pi[G_t\mid S_t=s]$.

Insufficient coverage or too few updates can leave estimates unstable. Converging value estimates is also different from finding an optimal policy: prediction evaluates a given policy; control additionally improves it. Before values have converged, the bootstrap term is itself approximate. Learning rates, exploration settings, alternative TD targets, and function approximators all affect practical training behavior.

## 5.4 n-step temporal difference \{#54-n-步时序差分}

The target $R_{t+1} + \gamma V(s_{t+1})$ bootstraps after one step: **TD(0)**. We can instead collect $n$ rewards before bootstrapping:

$$
\begin{equation}\label{eq:n_step_td_annotated}
G_t^{(n)} =
\underbrace{R_{t+1} + \gamma R_{t+2} + \cdots + \gamma^{n-1} R_{t+n}}_{\textcolor{blue}{\text{sampled rewards}}}
+ \underbrace{\gamma^n V(s_{t+n})}_{\textcolor{red}{\text{bootstrapped estimate}}}
\end{equation}
$$

The first term is the discounted sum of $n$ rewards sampled after step $t$. The second uses the estimated value at $s_{t+n}$. Increasing $n$ uses more observed rewards and discounts the bootstrap term more strongly; decreasing $n$ relies more on the current value estimate and permits earlier updates.

The limiting cases connect TD and Monte Carlo:

$$
\begin{equation}\label{eq:n_step_td}
\begin{aligned}
& n=1(\mathrm{TD}) \quad G_t^{(1)}=R_{t+1}+\gamma V\left(s_{t+1}\right) \\
& n=2 \quad G_t^{(2)}=R_{t+1}+\gamma R_{t+2}+\gamma^2 V\left(s_{t+2}\right) \\
& n=\infty(\mathrm{MC}) \quad G_t^{\infty}=R_{t+1}+\gamma R_{t+2}+\cdots+\gamma^{T-t-1} R_T
\end{aligned}
\end{equation}
$$

For an episodic task, collecting rewards through termination gives the complete Monte Carlo return. Smaller $n$ typically means more bootstrap bias and less variance; larger $n$ typically reduces that bias while increasing variance and the delay before updating. Thus $n$ controls a tradeoff among computation, accuracy, bias, and variance.

## 5.5 Comparing dynamic programming, Monte Carlo, and TD \{#55-动态规划蒙特卡洛和时序差分的比较}

| Method | Environment model | Update timing | Estimation | Main tradeoffs |
| --- | --- | --- | --- | --- |
| Dynamic programming | Required | During value-update sweeps | Bootstrapping | Can converge quickly, but requires a complete environment model |
| Monte Carlo | Not required | After an episode | Sampling | Unbiased complete-return samples for a fixed policy; requires full episodes and often has high variance |
| Temporal difference | Not required | Each interaction step | Sampling and bootstrapping | Timely, efficient updates with lower variance; bootstrap bias and sensitivity to exploration and learning settings |

## 5.6 Sarsa \{#56-sarsa-算法}

**Sarsa** is an **on-policy** TD control algorithm for estimating $Q(s,a)$. Its name refers to the five elements in an update: state $S_t$, action $A_t$, reward $R_{t+1}$, next state $S_{t+1}$, and next action $A_{t+1}$.

### 5.6.1 TD estimation of action values \{#561-时序差分估计动作价值}

The action-value update is analogous to the state-value update:

$$
\begin{equation}\label{eq:td_q_update}
Q(s_t, a_t) \leftarrow Q(s_t, a_t) + \alpha [R_{t+1} + \gamma Q(s_{t+1}, a_{t+1}) - Q(s_t, a_t)]
\end{equation}
$$

### 5.6.2 Sarsa procedure \{#562-sarsa-算法流程}

Combining the control loop with TD action-value estimation gives the following procedure. **See the practice material for complete implementations.**

1. Initialize $Q$. Reset the environment to $s_0$ for each episode and select $a_0$ using an $\varepsilon$-greedy policy.
2. Starting at $t=0$, execute $a_t$ and observe $r_{t+1}$ and $s_{t+1}$.
3. If $s_{t+1}$ is terminal, update $Q(s_t,a_t)$ toward $r_{t+1}$ and end the episode.
4. Otherwise, select $a_{t+1}$ in $s_{t+1}$ using the same policy. Update $Q(s_t,a_t)$ toward $r_{t+1}+\gamma Q(s_{t+1},a_{t+1})$.
5. Set $t\leftarrow t+1$ and repeat steps 2–4, executing the action already selected.

Sarsa updates without waiting for episode completion, using $s_t,a_t,r_{t+1},s_{t+1}$ and the next action $a_{t+1}$ selected by the same policy. No next action is selected after reaching a terminal state.

### 5.6.3 Exploration policy \{#563-探索策略}

Sufficient exploration is important for learning values. Sarsa commonly uses an **$\varepsilon$-greedy policy** to balance exploration and exploitation: select a currently best action with probability $1-\varepsilon$, or a uniformly random action with probability $\varepsilon$.

$$
\begin{equation}\label{eq:epsilon_greedy}
\pi(a|s) =
\begin{cases}
1 - \varepsilon + \frac{\varepsilon}{|\mathcal{A}(s)|}, & \text{if } a = \arg\max_{a'} Q(s, a') \\
\frac{\varepsilon}{|\mathcal{A}(s)|}, & \text{otherwise}
\end{cases}
\end{equation}
$$

The exploration rate $\varepsilon$ is often reduced during training: explore broadly at first, then increasingly exploit what has been learned.

## 5.7 Q-learning \{#57-q-learning-算法}

**Q-learning** is an **off-policy** TD control algorithm. Instead of evaluating the action actually selected at the next state, it uses the highest estimated next-state action value. This lets it learn a greedy target policy while collecting experience with a different behavior policy:

$$
\begin{equation}\label{eq:q_learning_update}
Q(s_t, a_t) \leftarrow Q(s_t, a_t) + \alpha [R_{t+1} + \gamma \max_{a'} Q(s_{t+1}, a') - Q(s_t, a_t)]
\end{equation}
$$

<details>
<summary>In plain language: how does Q-learning's max differ from Sarsa?</summary>

Suppose the next state has two actions with estimates $2$ and $5$, and exploration actually selects the action worth $2$. With immediate reward $1$ and $\gamma=0.9$:

- Sarsa uses the selected action, giving target $1+0.9\times2=2.8$.
- Q-learning uses the highest estimated value, giving target $1+0.9\times5=5.5$.

Here $\max$ returns the score $5$; $\arg\max$ returns the action that achieves that score. Q-learning's target does not require executing that highest-scoring action next.

Quick reference: [on-policy and off-policy](/docs/foundations/rl-for-robotics/quick-reference#on-off-policy), [max and argmax](/docs/foundations/rl-for-robotics/quick-reference#notation).

</details>

The procedure is as follows. **See the practice material for complete implementations.**

1. Initialize $Q$ and reset the environment to $s_0$ for each episode.
2. Starting at $t=0$, choose and execute $a_t$ using a behavior policy such as $\varepsilon$-greedy. Observe $r_{t+1}$ and $s_{t+1}$.
3. If $s_{t+1}$ is terminal, update $Q(s_t,a_t)$ toward $r_{t+1}$ and end the episode. Otherwise, update toward $r_{t+1}+\gamma\max_{a'}Q(s_{t+1},a')$.
4. Set $t\leftarrow t+1$ and repeat steps 2–3. The maximum in the update target does not depend on the action actually selected next.

Q-learning uses $\max_{a'}Q(s_{t+1},a')$, while Sarsa evaluates the next action sampled by its policy. Q-learning focuses on the greedy policy and can learn aggressively; Sarsa accounts for the exploratory actions it actually takes. Their relative speed and stability depend on the environment and learning settings.

| | Q-learning | Sarsa |
| --- | --- | --- |
| Policy type | Off-policy | On-policy |
| Update target | Best estimated next action | Next action actually selected |
| Learning behavior | Often more aggressive | Accounts for behavior-policy exploration |
| Typical consideration | Learning a greedy policy while exploring | Evaluating the consequences of the policy actually executed |

## 5.8 On-policy and off-policy learning \{#58-同策略与异策略}

The distinction concerns the **behavior policy**, which collects experience, and the **target policy**, which is evaluated or improved. If they are the same, learning is on-policy; if they differ, learning is off-policy.

For a driving analogy, an on-policy learner evaluates and improves the driving behavior it currently follows. An off-policy learner may evaluate an idealized driving policy while collecting experience under different behavior dictated by traffic or road conditions.

On-policy methods learn directly from their current behavior. Off-policy methods offer more flexibility to reuse data from other behavior policies, but can face additional stability and convergence challenges.

## 5.9 Questions \{#59-思考}

**Are Monte Carlo and TD methods both model-free?**

Yes. They learn values or policies from interaction without requiring an explicit model of the environment's dynamics.

**What are their respective strengths and weaknesses?**

Monte Carlo methods learn directly from complete returns. For a fixed policy, those returns provide unbiased samples, but updates must wait for full episodes and can have high variance. Long or nonterminating episodes are problematic. TD methods learn during interaction, work with both episodic and continuing tasks, and can use function approximation in large state spaces. Bootstrapping introduces bias, and learning rate and exploration settings affect stability. Choose according to the task and the available experience.

**What is Q-value overestimation, and how can it be reduced?**

Overestimation occurs when learned state or action values exceed their true values because of sampling noise or properties of the learning algorithm. Double Q-learning separates action selection from evaluation to reduce this effect. Prioritized replay, target networks, and exploration strategies also affect data coverage and training stability, although they serve different roles from the direct overestimation correction in Double Q-learning.

**How do on-policy and off-policy methods differ?**

On-policy methods collect samples with the policy they are learning about. Off-policy methods can collect data with a different behavior policy and use it to improve their target policy.

**Why is exploration necessary?**

The optimal policy is initially unknown. Following only currently preferred actions can leave useful states and actions unexplored and miss better strategies. Common exploration mechanisms include $\varepsilon$-greedy policies, softmax sampling, and Gaussian action noise.
